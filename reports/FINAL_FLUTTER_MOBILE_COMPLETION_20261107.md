## Change

A Parent can still uncheck a chosen purpose. Fixture behavior is retained. A widget regression covers close and subsequent explicit agreement. No API payload, Parent Gate, proof, token, media or session policy changed.

## API and acceptance boundary

The client has real Parent registration/OTP/login, approved Terms parser, both independent Child notices, attempt/resume identities, Child create/read/consent enforcement, server-filtered catalog, fresh Child-token private-media grant, answer/complete/readback and gated history integrations. Empty catalog and no eligible lesson states explain that the server has not returned a suitable published lesson.

The Backend `ChildService.BeginAttemptAsync` and `GetAttemptAsync` currently project `NoticeRef` through `ToDto` without document bodies, while the approved document lives on the public reference. The client correctly refuses consent without the document attached to that exact attempt snapshot; the Frontend cannot truthfully fill this from a different snapshot. This is a source-level integration blocker, not an authenticated live response claim. Real Parent/mailbox/PIN authorization and age-eligible published media are also needed to verify Android end-to-end creation, playback bytes, completion persistence, expiry and withdrawn-consent behavior. No fictional guardian or child was created on Pilot. CMS authoring/media/review/publication is not live accepted here.
